# Разведка сайта магазина

Код не пишем. Результат: отчёт «что есть, сколько, как забирать». Решение предлагаем только после фактов.

## Порядок

1. **Что уже есть.** Прочитай текущий парсер магазина в `packages/scrapers/<магазин>/src/` и запомни, сколько товаров он даёт сейчас.
2. **Правила.** Открой `/robots.txt` и sitemap магазина. Выпиши, что закрыто. Не обходи запреты, спорное вынеси пользователю.
3. **Карта источников.** Playwright: открой главную, собери ссылки (категории, акции, буклеты, `/p/` карточки). Перечисли все места, где есть списки товаров.
4. **Данные внутри страницы.** Для каждого источника через `browser_evaluate` + `fetch` сравни: сколько плиток в HTML, есть ли встроенный JSON (`data-*`, `__NEXT_DATA__`, `ld+json`), есть ли пагинация или «загрузить ещё».
5. **Скрытый API.** Если плиток меньше, чем должно быть: нажми «ещё» через `browser_run_code_unsafe` и перехвати запросы (`page.on('request')`, фильтр от аналитики и статики). Проверь: работает ли URL голым `fetch` без cookies, максимальный `fetchsize`, как считается `offset`, есть ли `total`.
6. **Охват.** Выкачай всё через найденный API и посчитай: всего, уникальных, без цены, действующих периодов. Сверь минимум с двумя независимыми источниками (sitemap, счётчик категорий). Числа из сериализованного состояния страницы не считай количеством, пока не увидишь контекст.
7. **Буклеты и картинки.** Проверь, есть ли структурированные товары (JSON, hotspots). Если только картинки, PDF и OCR-текст, так и скажи: нужен vision или OCR, оценка точности и цены.
8. **Сравнение.** Сколько товаров нашли против текущего парсера. Что нового: будущие периоды, категории, EAN, условия карты.

## Правила

- Только чтение. Ничего не писать в БД, не менять код, не слать запросов чаще, чем нужно для проверки.
- Каждое утверждение с цифрой: «71 из 71», а не «почти все». Чего не проверил, назови прямо.
- Не доверяй первой цифре в HTML. Подтверди её вторым источником.
- Секреты и cookies в отчёт не включать.

## Формат отчёта

1. Таблица источников: источник, что внутри, сколько, парсится ли.
2. Находки (API, URL с параметрами, лимиты, пагинация).
3. Что даёт сверх текущего парсера.
4. 2–3 варианта решения с плюсами и минусами, один рекомендованный.
5. Риски: robots.txt, нестабильность версии API, юридические и частотные ограничения.
6. Что нужно решить пользователю.

Дальше конвейер: `grilling` по открытым вопросам, план, тесты с фикстурой, реализация.
