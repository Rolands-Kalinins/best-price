## Безопасность

- [ ] **S1 (P1). Нет заголовков безопасности.** В `apps/web/next.config.ts` нет `headers()`: ни CSP, ни `frame-ancestors`/`X-Frame-Options`, ни `Referrer-Policy`, `X-Content-Type-Options`, `Strict-Transport-Security`. Сайт можно встроить в чужой iframe (кликджекинг админки). Сделать: заголовки в `next.config.ts`; CSP с `img-src https:` (картинки магазинов грузятся напрямую, `referrerPolicy="no-referrer"`), `connect-src` на Supabase, `script-src` под nonce/Next. Проверка: Playwright, консоль без нарушений CSP на `/grocery`, `/pharmacy`, `/login`, вход через Google.
- [ ] **S2 (P1). Парольный вход в боевом Supabase.** Advisor `auth_leaked_password_protection`: защита от утёкших паролей выключена. Вход на сайте только Google, поэтому правильнее отключить провайдер Email в боевом проекте (в сиде есть публичный `dev@bestprice.local` / `dev-password-123`, только локально). Проверить в панели Supabase, что Email-провайдер выключен или регистрация по нему закрыта; иначе включить защиту. Действие в боевом проекте только после подтверждения.
- [ ] **S3 (P2). Открытая регистрация и нагрузка на поиск.** Любой Google-аккаунт читает данные и гоняет поиск (`ilike`/`or()` по `search`) без ограничений (риск описан в `docs/PLAN.md`). Оценить: лимит длины запроса (проверить `parsePharmacyQuery`/`parseOfferQuery`), число слов в `searchGroups`, при необходимости rate limit в `proxy.ts` или возврат закрытого доступа (`is_member()` по `allowed_emails`, решение владельца).
- [ ] **S4 (P2). Фаззинг поиска.** `searchOrClause` собирает фильтр PostgREST из пользовательского текста (уже были ошибки: `docs/findings/2026-10-27-search-escape-backslash.md`). Добавить в `packages/core` тест на запятые, скобки, точки, кавычки, `\`, `%`, `_`, очень длинные строки: фильтр не должен ломаться или расширяться.
- [ ] **S5 (P3). Таблицы с RLS без политик.** Advisor: `grocery.pair_checks`, `grocery.pair_verdicts`, `grocery.title_attrs`. Скорее всего намеренно (только service role). Подтвердить, что `authenticated` и `anon` не имеют grants, и записать в комментарии к миграции «политик нет намеренно».
- [ ] **S6 (P3). Функции `is_admin`, `is_member`, `last_scrape_success` доступны `authenticated`** (advisor WARN). Это намеренно (вызываются через `rpc` сайта, возвращают только булево/метку). Принять риск и записать в `docs/PLAN.md`, чтобы предупреждение не пугало повторно.
- [ ] **S7 (P3). Сообщения БД в админке.** `updateOffer` выводит `error.message` Supabase в адрес `?err=` (видит только админ). Низкий риск; заменить общим текстом, подробности в лог сервера.
- [ ] **S8 (P1, проверка). Зависимости.** Запустить `pnpm audit`, закрыть высокие и критические уязвимости, добавить шаг в `ci.yml` (не блокирующий или с порогом `high`).

## Удобство и доступность (UI/UX)

- [ ] **U1 (P2). Вход без обратной связи.** `app/login/page.tsx`: кнопка «Войти через Google» не блокируется после нажатия (можно нажать дважды), ошибка `signInWithOAuth` не показывается. Сделать состояние «Перехожу…» с `disabled`, при ошибке перенаправить на `/login?error=1`.
- [ ] **U2 (P2). Закреплённые панели закрывают фокус.** Шапка (`top-0`, 56 px) и строка поиска (`top-14`) закреплены; при Tab по карточкам и чипам сфокусированный элемент может уйти под них (WCAG 2.4.11). Добавить `scroll-margin-top` (≈ 7rem) на карточки и кнопки ленты; проверить клавиатурой в Playwright.
- [ ] **U3 (P2). Нет `not-found` и `global-error`.** В `apps/web/app` есть только `error.tsx` разделов. Любой неверный адрес и сбой корня показывают стандартную страницу Next. Добавить `app/not-found.tsx` (ссылка на `/grocery`) и `app/global-error.tsx` по стилю существующих страниц.
- [ ] **U4 (P3). Мёртвая страница «Доступ закрыт».** `app/page.tsx`: после открытой регистрации `is_member()` истинна для любого с email, ветка «не в списке» почти недостижима, текст устарел. Упростить до редиректа, если нет сценария без email.
- [ ] **U5 (P3). Язык названий товаров.** `<html lang="ru">`, названия латышские: скринридер читает их по-русски. Добавить `lang="lv"` на заголовки карточек (минимум для `h2` с названием).
- [ ] **U6 (P3). Форма пароля в dev.** Поля без `label` и `autoComplete` (`app/login/page.tsx`, только `pnpm dev`). Добавить `aria-label` и `autoComplete="email"/"current-password"`.
- [ ] **U7 (P2, проверка). Живая проверка интерфейса.** Playwright: iPhone-ширина 360 и 390, десктоп 1280, светлая и тёмная тема, клавиатура на фильтрах и меню профиля, контраст `text-muted-foreground` на `bg-card` (мелкий `text-xs`), масштаб 200 %. Результат оформить новыми задачами.
- [ ] **U8 (P2, проверка). Админка.** Прочитать и проверить по правилам `app/grocery/admin/*/page.tsx` и `components/admin-nav.tsx` (формы: подписи, ошибки рядом с полем, подтверждение разрушающих действий, мобильная ширина).
