# Журнал версий

Формат версии `А.Б.В.Г` и правила повышения: раздел «Версия приложения» в `CLAUDE.md`. Заметки релиза на GitHub берутся из раздела нужной версии.

## 1.8.0.1 — 2026-10-31
- Локальная копия боевых данных: `pnpm db:pull` (`scripts/db-pull.mjs`). Раньше локальная БД была пустой (0 акций против 7666 на боевой), и на localhost нельзя было проверить ни страницы, ни фильтры, ни сопоставление. Теперь одной командой в локальную БД копируются акции, история цен, группы товаров, решения админа по сопоставлению, кэш Gemini (бренды и вердикты), учёт квоты и журнал запусков; на localhost те же 6928 акций в ленте, что и на сайте.
- Боевая БД только читается (ключ из `.env.prod`), локальная заменяется одной транзакцией: сбой посреди копирования оставляет её как была. Не копируются `users` и `allowed_emails` (там email; локально остаётся `dev@bestprice.local`) и `leaflet_offers` (пока только локальная таблица).
- Нюансы, найденные при первом запуске: вычисляемые столбцы `offers.discount` и `offers.search` нельзя вставлять в готовом виде (список столбцов без них); триггер `log_price` при вставке акций сам создаёт строки истории «на сегодня», поэтому история перед копированием очищается (иначе 15016 строк вместо 7547). После копирования все 10 таблиц совпали с боевой по числу строк.

## 1.8.0.0 — 2026-10-30
- Новая страница `/grocery/admin/scrapers` (только админ, пункт «Парсеры» в меню профиля): статус последнего запуска каждого парсера (успех или сбой, время старта по Риге, длительность, акций и отброшенных, текст ошибки), предыдущие запуски, время и обратный отсчёт до ближайшего запуска по расписанию, кнопки «Запустить» (один парсер) и «Запустить все». Запуск идёт через `workflow_dispatch` GitHub Actions с входом `source` (`all` или слаг магазина); в `scrape.yml` добавлены вход, условия `if` у job'ов и `concurrency: scrape`, чтобы повторный клик не запускал два парсера сразу.
- БД: `scrape_runs` теперь читает только админ (раньше любой участник видел статусы и тексты ошибок). Метке «обновлено X назад» участников отдаёт функция `public.last_scrape_success()` (security definer, только время последнего успеха). Миграция `20261030100000_scrape_runs_admin_only.sql`; применять до выката кода.
- Расписание вынесено в `core` (`SCRAPE_CRON`, `nextScrapeAt`, `formatCountdown`); тест сверяет `SCRAPE_CRON` с cron в `scrape.yml`.
- Для кнопок нужен секрет `GITHUB_DISPATCH_TOKEN` в Vercel (fine-grained PAT, только этот репозиторий, Actions: read and write). Без него страница работает, кнопки показывают подсказку.
- Отложено: состояние «выполняется сейчас» (парсеры пишут в журнал только в конце запуска), пометка «вручную/по расписанию».

## 1.7.0.1 — 2026-10-29

## 1.7.0.0 — 2026-10-28
- Общие категории и фильтр по ним. На странице `/grocery` над лентой чипы категорий (Мясо, рыба и птица, Молочные продукты, Хлеб и выпечка, Напитки, Бытовая химия и др., всего 19 + «Другое»), фильтр действует и на карточки «Где дешевле». Параметр `?cat=`.
- Как раскладываем: словарь латышских основ в `packages/core/src/categories-data.ts`, функция `categorize` (самая длинная основа побеждает), без Gemini на каждый товар. Gemini один раз предложил список категорий и основы (5 запросов), дальше словарь доработан вручную. Это сняло риск лимитов (500 запросов в сутки) и работает для новых акций каждую неделю.
- Шаг `categorize` в workflow `match` (после сопоставления, выполняется и при его сбое) пишет `offers.cat` только там, где значение изменилось. `pnpm --filter @bestprice/matcher categorize --dry` показывает охват и частые слова без категории.
- Миграция `offer_category` (только добавление: столбец `grocery.offers.cat`). Применять к боевой БД до слияния кода, затем запустить `categorize` (старый код столбец не читает).
- Охват на боевых данных: без категории ~1,7% акций; точность по выборке порядка 90% (ошибки: фрукт или овощ внутри готового продукта и др.). FR-42 изменён: раньше «общих категорий нет».

## 1.6.0.0 — 2026-10-28
- Мониторинг лимитов Gemini в админке (`/grocery/admin/ai`, пункт «Лимиты Gemini» в меню профиля админа): запросов за сегодня из суточного лимита (полоса и %), токены на входе и выходе, ошибки, отметка «квота исчерпана (429)» со временем по Риге, время до сброса и история за 14 дней. Лимиты модели (`gemini-3.1-flash-lite`: RPM 15, TPM 250K, RPD 500) лежат в `grocery.ai_limits`; меняются вручную в SQL, когда Google меняет лимиты.
- Матчер считает расход: все HTTP-запросы к Gemini (включая повторы и неудачные), токены из `usageMetadata`, ошибки и ответы 429; записывает через функцию `grocery.add_ai_usage` (атомарное приращение) по дню Лос-Анджелеса (в полночь по нему Google сбрасывает суточный лимит). Считаются только запросы матчера: остальное на проекте Google (AI Studio, другие приложения) не видно. Расход пишется и в `--dry`, он тратит настоящую квоту. Сбой записи учёта матчер не роняет.
- Миграция `ai_usage` (только добавление: `ai_limits`, `ai_usage`, `add_ai_usage`, чтение только админу, запись только сервисной роли). Применять к боевой БД до слияния кода.

## 1.3.0.0 — 2026-10-28
- Сопоставление товаров между магазинами: один и тот же товар (бренд, размер, слова названия и количественное условие совпадают полностью) показывается одной карточкой «Где дешевле» с ценами по магазинам. Бренд, размер и слова берём из названия (`packages/core/src/match.ts`): EAN есть только у Etop, бренд у Rimi и Maxima отсутствует. Карта магазина условием не считается (бейдж), «от 2 шт.» и «цена за 2 шт.» должны совпасть.
- Неуверенные пары попадают в админ-очередь `/grocery/admin/matches` (только админ): «Тот же товар» или «Разные»; решение хранится по ключу пары, а не по id акции (ключи Maxima меняются каждую неделю). Пока решения нет, акции остаются обычными карточками.
- Миграция `product_matching` (только добавление): `grocery.products`, `match_decisions`, `match_suggestions`, `offers.product_id`. Пакет `@bestprice/matcher` (`pnpm --filter @bestprice/matcher match`, режим `dry` без записи) и workflow `match.yml` (после `scrape` и вручную).
- Лишнюю акцию можно убрать из предположения кнопкой «Убрать из сопоставления» (таблица `grocery.match_exclusions`, миграция `match_exclusions`); убранные видны внизу страницы с кнопкой «Вернуть». Тот же раздел «Объединённые товары» показывает подтверждённые группы, из них акцию тоже можно убрать. Убранная акция сразу исчезает из очереди, из сопоставления выпадает при следующем запуске `match`.
- Фото акций в очереди админа и в карточке «Где дешевле» (у каждого магазина своё); нажатие открывает фото крупно в окне (`components/zoom-image.tsx`, нативный `<dialog>`: Esc, клик по фону и кнопка ×).
- Правки после код-ревью до релиза: решения и исключения матчер читает страницами (потолок 1000), защита `match` считает акции с привязкой до и после, лента скрывает только акции, показанные в карточках, `250gr` без пробела распознаётся, запрос товаров с `offers!inner`. Подробности: `docs/findings/2026-10-28-matching-review-round2.md`.
- Боевая БД 2026-10-28: применены `product_matching`, `match_keys_c_collation`, `match_exclusions` (советники без новых замечаний); после последнего запуска `match`: 68 товаров, 144 акции в группах, 68 предположений.
- Первый запуск на боевой БД (на момент выпуска версии, до новых данных): 6665 акций, 62 товара (131 акция), 78 предположений.
