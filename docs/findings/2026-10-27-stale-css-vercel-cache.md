# Боевой сайт собрался со старым CSS: светлый шаблон вместо нашей темы

**Что случилось.** После релиза 1.1.0.0 владелец заметил, что сайт на Vercel стал белым (раньше при тёмной системной теме он был тёмным, с зелёными акцентами). Через Playwright с эмуляцией `prefers-color-scheme: dark` боевая `/login` осталась белой: `--background` был `oklch(1 0 0)`, шрифт не Inter, `color-scheme: normal`.

**Что установлено.**
- В боевом CSS (35 969 байт) лежал **старый шаблон shadcn** (`:root{--background:#fff}`, `.dark{…}`, sidebar-переменные), без `--sale` и без `prefers-color-scheme`, но с новым классом шрифта из нового `layout.tsx`.
- В репозитории `globals.css` на коммите сборки (`bbc95c3`) новый. Локальная `pnpm build` того же коммита даёт правильный CSS (35 102 байта, есть `--sale` и `prefers-color-scheme:dark`).
- В журнале сборки Vercel: `Restored build cache from previous deployment (DjxkJTBYjHPejjQmVwx2fPTFGDpU)`, то есть кэш старого боевого деплоя. То же в превью PR. Постоянный кэш сборки Turbopack (`.next/cache/turbopack`) включён по умолчанию с Next 16.3.

**Почему возникла.** Не доказано до конца. Самая вероятная причина: Turbopack на Vercel переиспользовал закэшированный результат обработки CSS (через наше пользовательское правило `@tailwindcss/turbopack` в `next.config.ts`) вместо пересчёта. Воспроизвести локально не удалось: сборка старого коммита, затем нового коммита поверх того же `.next` даёт правильный CSS. Значит, на Vercel сработало что-то в связке «свежий клон + восстановленный кэш», чего локально нет.

**Как исправлено.** В `apps/web/next.config.ts`: `experimental.turbopackFileSystemCacheForBuild: false`. Проверено локально: сборка не пишет `.next/cache/turbopack`. Цена: сборка на Vercel чуть дольше (около 30 секунд всего). Добавлена проверка `scripts/build-css.test.mjs`: собранный CSS обязан содержать тёмную тему и `--sale` и не содержать шаблонный `--background:#fff` (красный на старом CSS, зелёный на настоящем). В CI `pnpm build` теперь выполняется до `pnpm test`.

**Как повлияло на остальной код.** Только конфигурация сборки и CI: код сайта и данные не менялись.

**Что ещё не проверено.** Что на боевом деплое после этого релиза CSS действительно новый. Если там останется старый, гипотеза про кэш Turbopack неверна: тогда пробовать принудительную сборку без кэша Vercel (`VERCEL_FORCE_NO_BUILD_CACHE=1` в переменных проекта, нужно подтверждение владельца).

**Как не допустить.**
- После выкладки открывать боевой сайт и сверять результат с локальной сборкой (CSS-переменные, цвета), а не считать «деплой завершён» признаком «выглядит как задумано».
- Проверка CSS в CI ловит ошибки в самом коде и конфигурации Tailwind, но не порчу, возникшую только на Vercel: её ловит ручная проверка после выкладки.
