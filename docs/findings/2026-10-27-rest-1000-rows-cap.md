# `.limit(10000)` не снимает лимит API в 1000 строк

**Что случилось.** В `packages/scrapers/rimi/src/run.ts` я читал известные периоды акций запросом с `.limit(10000)`. Ошибку нашёл при проверке перед первым боевым запуском, до того как она проявилась.

**Почему.** Supabase API (PostgREST) отдаёт не больше 1000 строк за запрос, `limit` выше этого значения не действует, и данные обрезаются молча, без ошибки. При ≈4000 акций Rimi парсер знал бы о ≈1000, а остальные карточки скачивал бы заново каждый день. Та же причина стояла за исходной проблемой страницы (`select *` по всем акциям).

**Как исправлено.** Чтение страницами по 1000 через `.range()` с `.order("id")` (стабильный порядок), запись частями по 500. Страница `/grocery` берёт не больше 1000 строк (`MAX_OFFERS`) и листает через `range` и `count`.

**Влияние на остальной код.** Парсеры Maxima и Lidl не менялись: у них меньше 1000 строк, но при росте они упрутся в то же ограничение (если станут читать таблицу).

**Как не допустить.** Любое чтение из таблицы, которая может вырасти выше 1000 строк, делать страницами с `.range()` и явным `.order()`. Лимит строк ответа учитывать при проектировании запросов.
