# Константа из клиентского модуля в серверной странице

**Что случилось.** После переезда фильтрации на сервер страница `/grocery` упала: `(intermediate value).split is not a function` в `.select(OFFER_COLUMNS, …)`. Пользователь видел «Не удалось загрузить акции».

**Почему.** Список столбцов `OFFER_COLUMNS` я объявил и экспортировал из `components/offer-card.tsx`, а там стоит `"use client"`. Серверный компонент, импортируя из клиентского модуля не-компонент, получает не значение, а заглушку-ссылку (client reference). Строку из неё не вызвать. `tsc`, `lint` и `build` это не ловят: тип у константы корректный, падает только при исполнении страницы, а страница закрыта входом через Google, и сам я её не открывал.

**Как исправлено.** Константа перенесена в `app/grocery/page.tsx` (серверный файл). В `offer-card.tsx` остался только тип `OfferRow` (типы стираются при сборке и безопасны). В комментариях у обоих мест указана связь «столбцы должны совпадать с `OfferRow`».

**Влияние на остальной код.** Нет: поведение страницы и карточки не менялось, тип `OfferRow` прежний. Других импортов значений из клиентских модулей в серверный код нет (проверено по `page.tsx`: импортируются только компоненты и функции `@bestprice/core`).

**Как не допустить.**
- Значения (константы, функции), нужные серверу, не экспортировать из файлов с `"use client"`. Клиентский модуль может отдавать серверу только компоненты и типы.
- Перед «готово» запускать страницу или те же запросы вживую (правило «Проверка исполнением» в `CLAUDE.md`).
