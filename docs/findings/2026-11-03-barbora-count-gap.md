# Barbora: прогон падал из-за `count`, который включает недоступные позиции

## Что случилось
Прогон scrape 2026-11-03 завершился ошибкой «получено 3021 из 3043 позиций 50XV, пагинация могла измениться». Пагинация не менялась.

## Почему возникло
Я считал, что `count` в ответе API равен числу отдаваемых позиций, и требовал `получено >= count`. В живом ответе `count` включает позиции, которые API не отдаёт ни при каком Limit: Akcijas 1685 уникальных из 1729, Paldies 2425 из 2443 (Limit 50, 100 и 200 дают один и тот же набор). Страницы приходят с недобором (199, 160, 128 из 200). Раньше расхождение не проявлялось или было нулевым, поэтому тесты и разведка его не показали.

## Как исправлено
Проверка полноты стала с допуском: сбой, если получено меньше `count × 0.95` (`MAX_MISSING` в `packages/scrapers/barbora/src/index.ts`). Усечение страниц по потолку Limit (как у Maxima) даёт потерю в десятки процентов и по-прежнему ловится. Тест воспроизведён до фикса (1000 из 1022 → сбой).

## Как повлияло на остальной код
Только `collection()` в парсере Barbora. `parse`, схема и другие парсеры не менялись.

## Как не допустить снова
Сверку с `count` у чужого API делать с допуском и проверять на живых данных, что `count` достижим (набор уникальных id при разных Limit), а не принимать счётчик за гарантию.
