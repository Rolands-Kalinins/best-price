# Условие акции Barbora не распознавалось сопоставлением

**Что случилось.** В парсере Barbora для скидки «2 vai vairāk −30%» я записал условие «Pērkot 2 vai vairāk». Тесты парсера были зелёные, но `conditionKind` (`packages/core/src/match.ts`) понимает только «N un vairāk» (`minN`) и «cena par N gab» (`setN`); любой другой текст он считает незнакомым и не сопоставляет. 358 из 3060 акций Barbora (все `CategoryPercentage`) никогда не склеились бы с другими магазинами, и ошибки при этом нигде не было бы видно.

**Почему возникла.** Формат условия я выбрал по смыслу, не прочитав, как его разбирает сопоставление. Тест проверял строку, а не её роль: «условие есть» ничего не говорило о том, склеится ли товар.

**Как исправлено.** Условие теперь «2 un vairāk» (формат Rimi), в тесте парсера добавлены вызовы `conditionKind` для всех трёх видов условия (`min2`, `set2`, карта = пустое условие). Нашёл при проверке перед коммитом (чтение `match.ts` для сверки форматов), на сайт и в боевую БД ошибка не попала.

**Влияние на остальной код.** Только строка условия внутри `packages/scrapers/barbora`. `match.ts` и остальные парсеры не менялись.

**Как не допустить.**
- Строку, которую потом разбирает чужой код (условие акции, период, категория), в тесте парсера прогонять через этот разборщик, а не сравнивать с литералом.
- Новый магазин: перед выбором форматов прочитать `conditionKind` и тесты Rimi и Maxima, сверить условия с ними.
