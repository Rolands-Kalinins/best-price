# 2026-11-15: в ветку PR запушены маркеры конфликта

**Что случилось.** При слиянии `main` в `docs/e-latts-off` скрипт-разрешение конфликта не нашёл блок `<<<<<<<`, но следующие команды (`git add -A`, `commit`, `push`) выполнились и выложили файлы с маркерами. `main` не пострадал, исправлено следующим коммитом.

**Почему.** (1) Регулярное выражение искало `\n`, а в рабочей копии Windows файлы с CRLF. (2) Команды были разделены `;`, а не `&&`, поэтому сбой скрипта не остановил коммит. (3) `release check` проверяет миграции и версию, но не маркеры конфликта, и показал «зелёный».

**Как исправлено.** Скрипт переписан: сначала приведение CRLF к LF, при отсутствии блока `sys.exit`; маркеры убраны, версия 2.16.0.2, запись в CHANGELOG.

**Влияние на остальной код.** Нет: затронуты только `VERSION` и `docs/CHANGELOG.md` в ветке PR #22 до слияния.

**Как не допустить снова.** Перед `git add` в разрешении конфликта проверять `grep -c '<<<<<<<\|>>>>>>>'` и прерываться, если не 0; шаги коммита и push цеплять через `&&` после проверки, а не через `;`.
