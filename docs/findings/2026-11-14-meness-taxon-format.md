# Mēness: сайт сменил формат категорий, все товары стали «не разобрано»

## Что случилось
Ночные прогоны 13 и 14.11 упали: `Mēness: не разобрано 10924 из 10924 товаров, формат мог измениться` (до этого с 11.11 были обрывы соединения, см. [meness-connection-drops](2026-11-12-meness-connection-drops.md): это другая причина). Данные на сайте остались от прогона 06.11.

## Почему возникло
API перестал отдавать `slug` в `productTaxons` (только `{id}`). `category()` делала `slug.split`, исключение ловил `parse()` и считал товар невалидным. Категория осталась в `mainTaxon` цепочкой `parent` с кодами через «_» (`menessaptieka_master/all_products/vitamini_un_mineralvielas/...`). Найдено по артефакту `meness-debug` (первая страница ответа): `parse()` на нём давал 0 из 100.

## Как исправлено
`packages/scrapers/meness/src/index.ts`: категория из `mainTaxon`, без двух служебных корней, «_» → «-». Убраны `MENU` и `SERVICE` (нужны были, чтобы выбирать из десятков деревьев; теперь дерево одно). Тесты переведены на новый формат. Живой прогон без записи в БД: 10 198 товаров, 0 не разобрано.

## Как повлияло на остальной код
Только Mēness. Категории прежнего вида (`skaistumam/...`, `vitamini-un-mineralvielas/...`) совпадают со словарём `pharmacy-categories`. Появились верхние уровни, которых не было при выборе «из меню» (`majdzivnieki`, `tests`, `komplekti`, `travel-products`…): раньше такие товары брали запасную ветку или оставались без категории.

## Как не допустить снова
Защита «не разобрано > 5%» сработала правильно, ошибку исполнения она показала, но не причину: исключение в `parse()` глотается. Если формат снова поменяется, смотреть артефакт `meness-debug` и гонять на нём `parse()` локально.
