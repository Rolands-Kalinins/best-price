# Apotheka (apotheka.lv) — разведка 2026-11-01

Группа: аптеки. Magento (PWA-тема), Apache, рендер на сервере. Открывается обычным `fetch`.

## Правила
`robots.txt` закрывает `/catalog`, `/catalogsearch`, `/customer/*`, `/checkout`, `/rest` (кроме `/rest/V1/sas/`), `/productalert`, `/stockQuantity` и ряд служебных. Страницы товаров лежат в корне (`/<slug>-pmm0179148lv`), разделы в `/produkti/...`, то есть не закрыты. REST Magento (`/rest/V1/...`) закрыт, поэтому им не пользуемся. Sitemap: `/sitemap_lv.xml`.

## Охват
- Sitemap: 11 683 адреса, из них по шаблону `...-pmm\d+lv` **9 133 товара**, остальное разделы (`/produkti/...`, `/piedavajumi/...`, бренды `/razotaji`), статьи.
- Счётчик списка на странице не найден (регулярка по «preces/rezultāti» ничего не дала), число сверено только по sitemap. Сверку вторым источником сделать при реализации.

## Источники
| Источник | Что внутри | Как |
|---|---|---|
| `/produkti/<раздел>?p=N` | плитки: артикул (`data-testid="product-card-PMM0015950LV"`), название, `<del>` старая цена, `<ins><data value="5.99">` цена со скидкой, значок `-11%` | `?p=N` работает (разные плитки на 1, 2, 3); `?page=` игнорируется. ≈32–34 плитки на страницу, страница ≈0.6 МБ |
| Страница товара `/<slug>` | ld+json `Product`: `sku`, `name`, `brand.name`, **`gtin`** («3273819215102»), `offers.price`, `availability`; мета `product:price:amount` | 420 КБ на страницу |
| `/piedavajumi/visi-ipasie-piedavajumi/...` | разделы акций («Mēneša piedāvājumi», «Noliktavas atlaides», «Kosmētikas ceturtdiena») | серверный HTML, не разбирали |

- На плитке **нет** бренда и GTIN. Бренд и штрихкод только на странице товара. Периодов акций не нашли.
- Числа: «cards» на `/produkti/skaistums` 34 уникальных на страницу (проверено на страницах 1–3).

## EAN
`gtin` есть на странице товара (проверена одна страница). Доля заполненных по каталогу не измерена.

## Варианты решения
1. **Списки + дозапрос карточек только за GTIN новых товаров** (рекомендую): ≈280 страниц списков (цена, акция), карточку каждого товара забираем один раз и храним `gtin` в БД; повторный обход только для новых артикулов. Первый прогон долгий (до 9 100 страниц × 420 КБ ≈ 3.8 ГБ), следующие лёгкие.
2. Только карточки из sitemap: самый полный, но тяжёлый ежедневно.
3. Только списки без GTIN: сопоставление по названию и размеру.

## Риски
Тяжёлый первый прогон, нет периода акций, порядок плиток в разделах может смещаться. Блокировки GitHub не проверялись.
