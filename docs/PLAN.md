# BestPrice — план проекта

Закрытый pet-проект для себя, семьи и друзей (до 20 человек). Сбор акций из магазинов Латвии. Без заработка. Интерфейс на русском, названия товаров в оригинале (латышский).

## Стек (всё бесплатно)

| Слой | Выбор |
|---|---|
| Фронтенд | Next.js (App Router), Tailwind, shadcn/ui, Vercel Hobby |
| БД и авторизация | Supabase free: Postgres, Google OAuth, RLS. Запросы через `supabase-js` и сгенерированные типы, без ORM |
| Парсеры | TypeScript, `fetch` + cheerio, валидация zod. Playwright только если сайт без него не открывается |
| Запуск парсеров | GitHub Actions по cron, раз в сутки в 06:00 (Рига). Ручной запуск через интерфейс GitHub |
| Репозиторий | Один приватный monorepo, pnpm workspaces: `apps/web`, `packages/core`, `packages/scrapers/*` |

## Архитектура

Изоляция отказов, а не отдельные серверы:

- Общее ядро: `users`, `sources`, `scrape_runs`.
- Каждый раздел: своя схема БД (`grocery.*`, позже `energy.*`), свой модуль во фронтенде, свой пакет парсеров.
- Разделы подключаются через один файл-реестр. Скрипт `pnpm new-module` создаёт шаблон нового раздела.
- Упал парсер — сайт работает. Каждый запуск пишется в `scrape_runs`. У каждого магазина метка «обновлено X назад». Устаревшие акции скрываются по дате окончания. О сбое уведомляет GitHub Actions по email.

## Доступ

- Вход только через Google и только для email из белого списка (проверка в RLS).
- Роли: `admin` (владелец) и `member`.
- Избранное и список покупок у каждого свои. Общие списки позже.

## Данные продуктов

- Берём только акции.
- История цен: одна строка в день на товар и магазин, только при изменении цены. Старше 6 месяцев удаляем.
- Даты акции берём из источника (Maxima, Lidl, Etop). Где их нет (Rimi): акция действует, пока товар виден в ежедневном запуске, пропал — закрываем.
- Lidl: всё из «Актуальных предложений». Rimi: только товары со старой ценой.
- Условие акции («2 шт.») хранится текстом в поле `condition`. В сводке сравниваем цену за единицу (за кг или л), товары с условием помечаем значком.
- Сопоставление товаров:
  1. EAN, если есть (Etop). Совпадение сразу, без очереди.
  2. Fuzzy по бренду, названию и объёму. Высокая уверенность подтверждается автоматически, низкая идёт в админ-очередь. Решение админа запоминается.
- Общих категорий в первой версии нет, остаются категории магазина.
- Главная раздела: поиск, затем «товар → цены в магазинах» для сопоставленных и список свежих акций по магазинам для остальных. Фильтры по магазину и по значку «с условием».

## Парсеры по магазинам

| Магазин | Метод | Заметки |
|---|---|---|
| Lidl (`/c/aktualie-piedavajumi/a10028219`) | fetch + разбор `data-grid-data` (JSON в атрибуте) | первым, даты есть, старая цена не найдена |
| Maxima (`/piedavajumi`) | fetch + cheerio, подгрузка `POST /ajax/salesloadmore` (offset) | около 839 товаров, даты в `data-dates-interval`, Cloudflare |
| Etop (`/lv/visi-akcijas-produkti`) | JSON `GET /api/ProductCarousel/GetCarousel`, при необходимости Playwright | около 1000 товаров, даты и EAN есть, `SettingId` берётся из HTML |
| Rimi (`/e-veikals/lv/akcijas-piedavajumi`) | fetch + cheerio, `?currentPage=N` (40 на страницу) | около 3700 позиций, фильтр по старой цене, дат нет |

Правила парсера:

- Один запрос в секунду, один запуск в сутки, кэш ответов.
- Честный User-Agent (например `BestPriceBot (личный проект)`), соблюдение robots.txt.
- Защиту не обходим. Если магазин блокирует честный User-Agent, он уходит в ручной режим или «позже».
- Если GitHub Actions блокируется (вероятнее у Maxima), этот парсер запускается с ПК владельца через Windows Task Scheduler и пишет в Supabase.
- Сырые данные сохраняем только при сбое, как артефакт GitHub Actions на 7 дней. В БД они не попадают.
- Данные от парсера проходят валидацию zod до записи в БД.

## Этапы

1. **Каркас.** Monorepo, Next.js на Vercel, Supabase, вход через Google с белым списком, таблица `scrape_runs`.
2. **Lidl от начала до конца.** Парсер, БД, страница со списком акций и меткой «обновлено». Здесь же проверяем, не блокирует ли магазин GitHub Actions.
3. **Остальные магазины.** Maxima, Etop, Rimi по общему контракту парсера. Цена за кг или л.
4. **Сопоставление товаров.** EAN, нормализация, fuzzy, админ-очередь.
5. **Персональное.** Избранное и личный список покупок.
6. **Расширяемость.** Генератор модулей и раздел «Электроэнергия» как проверка шаблона.

## Не проверено

Выясняем по ходу этапов 2–3:

- Условия использования (ToS) всех четырёх сайтов.
- Блокировка IP GitHub Actions.
- Etop: как подгружаются товары после первых 60 («Rādīt vairāk»), точные ключи цены.
- Lidl: поле старой цены, пагинация, все ли тайлы являются акциями.
- Maxima: полная пагинация по offset и фильтры.
- Rimi: есть ли даты на страницах товаров.
