# Frontend: красивый и удобный интерфейс — план реализации

> **Для исполнителя:** REQUIRED SUB-SKILL: `superpowers:executing-plans` (или `subagent-driven-development`). Шаги отмечаются чекбоксами. Дизайн-решения принимает skill `frontend-design`, проверяет `web-design-guidelines`.

**Цель:** превратить пустой серый интерфейс в mobile-first каталог акций: шапка, сетка карточек с фото, поиск и фильтры в URL, светлая и тёмная темы.

**Архитектура:** серверная страница `/grocery` грузит акции как сейчас и отдаёт массив клиентскому компоненту ленты. Фильтрация и сортировка — чистые функции в `packages/core` (там уже есть `node --test` + `tsx`, новых зависимостей нет). Состояние фильтров живёт в URL (`useSearchParams`).

**Стек:** Next.js 16 (App Router, `cacheComponents`), Tailwind 4, shadcn/ui (base-ui), `lucide-react`, `next/font`. Новых зависимостей не добавляем.

**Спека:** решения допроса от 2026-10-25 (Q1–Q17, ниже), `docs/PLAN.md`, `tasks/prd-bestprice.md`.

## Решения допроса (зафиксировано)

- Skills: `frontend-design` (установлен) + `web-design-guidelines` для проверки.
- Mobile-first, десктоп как расширение. Светлая и тёмная тема по системе, без переключателя.
- Свежий «продуктовый» стиль: акцент зелёный; красный/оранжевый только для старой цены и скидки.
- Сетка карточек с фото: 2 колонки на телефоне, 3–4 на десктопе. Одна общая лента, не секции по магазинам.
- Шапка: логотип, раздел, меню профиля с выходом. Нижней панели нет до этапа «Персональное».
- `/` → редирект на `/grocery`. Остаются вход и «Доступ закрыт».
- Только фронтенд и существующие данные. БД и парсеры не трогаем.
- Состояния: скелетоны (`loading.tsx`), пусто, ошибка (`error.tsx`).
- Фильтры в URL: `?q=&store=&cond=1&sort=`.
- Картинки обычным `<img loading="lazy">` с фиксированным соотношением и заглушкой.
- Шрифт Inter (`latin`, `latin-ext`, `cyrillic`), цены с `tabular-nums`.
- Доступность: контраст AA в обеих темах, фокус, клавиатура, зоны ≥ 44 px, `prefers-reduced-motion`, состояние не только цветом.
- Клик по карточке: сайт магазина, новая вкладка, `rel="noopener noreferrer"`.
- Проверка каждого этапа: Playwright 375 и 1280 px, светлая и тёмная, консоль, `web-design-guidelines`, `pnpm lint`, `pnpm build`.

## Глобальные ограничения

- Интерфейс на русском, названия товаров в оригинале.
- Цены: `1,99 €`; цена за единицу `/кг` или `/л`; даты `Europe/Riga`.
- Нет новых зависимостей и изменений схемы БД.
- Секреты не печатать; service role в браузер не попадает.
- Ссылка `url` и `image_url` приходят из парсера: выводить только `http(s)`, иначе без ссылки/фото.
- Коммит и push только по просьбе пользователя.

## Review Focus

- Название товара с `<`, `&`, кавычками и эмодзи: выводится как текст, вёрстка не ломается.
- `url` или `image_url` с `javascript:`/пустой строкой: нет ссылки, нет фото.
- `price`, `old_price` равны или `old_price < price`: значок скидки не показывается, нет «−0%».
- Длинное название без пробелов (латышские составные слова): обрезается, не раздвигает сетку.
- Поиск по латышским диакритикам: «pienas» находит «Piens», «ā/š/ž» нормализуются.

## Этап 3. Поиск и фильтры

**Interfaces:** Produces в `offer-view.ts`:
`type OfferQuery = { q: string; store: number | null; cond: boolean; sort: "discount" | "price" | "ends" }`;
`parseQuery(sp: URLSearchParams): OfferQuery` (мусор → значения по умолчанию, `sort` по умолчанию `"discount"`);
`filterOffers(offers: Offer[], q: OfferQuery): Offer[]`;
`sortOffers(offers: Offer[], sort: OfferQuery["sort"]): Offer[]`.
